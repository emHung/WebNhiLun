# Supabase setup status

The draft initial schema and Storage bucket migration is in `migrations/202610140001_initial_schema.sql`. It has **not** been applied to any remote project. The Supabase MCP currently points to a different project with unrelated `public.profiles`, `public.pitches`, and booking tables, while frontend/backend configuration points to the intended project. A read-only Data API check against the configured URL did not find exposed `public.profiles` or `public.activities` tables, and Storage returned no buckets; this does not prove the underlying database is empty. Switch the MCP to the configured project or provide its database connection before applying the draft migration.

The seed importer reads `../data/seedData.js` and `../data/themes.json`. Preview it with `python backend/scripts/seed_supabase.py --dry-run` from the repository root. The current script refuses to create missing Auth users automatically. Once the VolunteerHub schema is safely deployed and demo users are explicitly provisioned, set a matching `SUPABASE_DB_URL` and run the reviewed seed import.

The legacy activity `ACT-004` refers to an organization absent from the four organization seed rows. The importer preserves its visible organizer name by creating a rejected `LEGACY-*` organization record that cannot be used to create activities. The legacy application `APP-2026-003` refers to an absent source account and keeps its legacy user id without linking it to a real account; certificates without a matching source application receive an unlinked legacy application row. Map original owners before enabling these records for account-specific workflows.

Do not put Supabase secret keys, database passwords, JWT secrets, or demo passwords in frontend files, source control, or chat. Never apply `202610140001_initial_schema.sql` to the current MCP project because it belongs to another app. Confirm the configured target project's schema through its own MCP connection or direct database connection first.
